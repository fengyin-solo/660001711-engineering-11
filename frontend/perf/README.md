# 渲染性能基线

固定一组显示参数跑渲染并逐帧计时，与上一次保存的门槛对照，防止"缩放/时间推进/图层开关一换，单帧从几毫秒跳到几十毫秒"的回归在没有重复测量手段的情况下溜进构建。

## 用法

```bash
npm run perf           # 本地开发：按 perf/baseline.json 门槛对照，超门槛退出码 1
npm run perf:update    # 重新实测并生成门槛（修改渲染逻辑或 perf.config.json 后运行，结果随代码提交）
npm run build          # 构建：vue-tsc + vite build 之后自动执行 npm run perf，共用同一份门槛
```

构建流水线与本地开发执行的是同一个脚本（`perf/run.mjs`）、读取的是同一份门槛（`perf/baseline.json`），不存在两套标准。

## 参数矩阵（perf.config.json）

- **缩放档位**：低（0.5x）/ 中（1.0x）/ 高（2.5x）
- **图层开关**：星名标签、星座连线、坐标网格三个开关的全部 8 种组合
- 合计 3 × 8 = 24 组；每组时间从固定起点按 1 小时间隔逐帧推进（模拟时间旅行），测量 200 帧（另有组内 30 帧预热与进程级 200 帧预热）

每组输出两个指标：截尾（丢弃最高 5% 的调度/GC 抢占离群帧）后的**平均帧耗时 meanMs**与**最差帧 worstMs**。

## 门槛规则

```
门槛 = max(实测值 × headroom(1.5), 实测值 + 抖动地板)
```

抖动地板 mean 为 0.05ms、worst 为 0.08ms：亚毫秒级耗时主要受机器调度噪声影响，绝对地板避免误报；当真实回归把耗时抬到几毫秒甚至几十毫秒时，倍数项自然生效。

超门槛时构建失败，日志逐组列出参数（缩放档位 id、zoom 值、三个图层开关状态）与 mean/worst 的实测值、门槛值、差值和百分比，例如：

```
✗ mid__all-on [zoom档位=mid(zoom=1), labels on | lines on | grid on]：mean 30.1ms > 门槛 0.139ms（+29.97ms (+21559.0%)）
```

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `perf.config.json` | 参数矩阵与测量设置（画布、时间起点/步长、帧数、缩放档位、图层组合、headroom/抖动地板） |
| `baseline.json` | 上次保存的门槛，**需要提交到仓库复用**；缺失/非法时流程报原因并中止（退出码 2），不会静默跳过 |
| `run.mjs` | 入口：esbuild 即时打包 TS 后交给 Node 执行，构建与本地共用 |
| `run-bench.ts` | 预热、逐帧计时、截尾统计、门槛生成与对照 |
| `config.ts` | 配置与门槛的加载、完整合法性校验、参数矩阵展开 |
| `mock-ctx.ts` | Node 下的 CanvasRenderingContext2D 替身（测量渲染器 JS 开销，可重复） |
| `.cache/` | 运行时打包缓存，已 gitignore |

被测渲染逻辑在 `src/render/frame.ts`，与 `StarCanvas.vue` 实时渲染共用同一份代码，基线测的就是线上路径。

## 异常处理原则

参数组合缺失（如 `layerCombos` 为空、未覆盖某开关的开/关、某组缺门槛）或门槛不合法（非正数、worst < mean、caseId 重复/不存在、schema 版本不符）时，日志明确说明出错字段与原因后中止，绝不静默跳过这一项。
